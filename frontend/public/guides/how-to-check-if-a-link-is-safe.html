How to check if a link is safe before you click

Most phishing succeeds not because the fake page is perfect, but because the link was never really looked at. This is the two-minute method defenders use — no tools required for the first steps, and a free checker for the rest.

1. Read the domain, right to left

A URL's identity is its registrable domain — the part immediately before the first single slash. In paypal.com.secure-login.xyz/login the domain is secure-login.xyz; "paypal.com" is just a subdomain decoration. In secure@paypal.com@evil.example/x, everything before the last @ is a username, and the real host comes after it. Attackers count on left-to-right reading. Read the host backwards and the tricks fall apart.

2. Look for look-alike spelling

Homograph and typosquat domains swap characters: paypa1.com (digit one), rnicrosoft.com (r+n posing as m), or a Cyrillic "а" that renders identically to a Latin "a". If a domain needs squinting, treat it as hostile. Aegis's link checker flags mixed-script hosts automatically — the human eye often cannot.

3. Distrust urgency, not just spelling

Plenty of phishing uses the real brand's name in the path of an unrelated or free-hosted domain (something.pages.dev/paypal-verify). The message around the link matters as much as the link: account freezes, parcel fees, refunds expiring, a boss who cannot talk — pressure is the payload. Slow down exactly when a message tells you not to.

4. Preview before you visit

On phones, long-press a link to see its true destination. For short links, run them through a redirect tracer so a server — not your browser — follows the chain and shows the final page. Never "just open it to see": modern phishing pages fingerprint and sometimes exploit on load.

5. Verify out of band

If the link asks you to log in, pay, or confirm anything, ignore it and go to the service the way you always do — the official app or a domain you type yourself. A legitimate request survives that detour; a phishing page cannot follow you there.

The 30-second checklist

  • Registrable domain is exactly the brand's real domain — no extra words, hyphens or strange TLDs.
  • No IP addresses, no @ tricks, no percent-encoded mush in the host.
  • The message's urgency has a reason that exists outside the message.
  • Redirects, if any, end on the same domain you expected.
  • When in doubt: navigate manually. Links are a convenience, not an obligation.
